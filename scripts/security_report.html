🔴 SEC-003 · Kritiek
Hardgecodeerde standaardwachtwoorden
admin/admin123 staat hardgecodeerd én zichtbaar op de inlogpagina. Elke misconfigureerde deployment is direct te compromitteren.

4. Kritieke bevindingen Rembro Beveiligingsaudit 2026
4.Kritieke bevindingen
De volgende drie bevindingen vereisen onmiddellijke actie. Ze vormen samen een directe dreiging voor de integriteit van de adminomgeving.
Kritiek SEC-001 Niet timing-safe token-vergelijking
Locatieserver/utils/auth.js:22
CategorieAuthenticatie · CWE-208
ProbleemDe requireAdmin-middleware vergelijkt het Bearer-token via !== (short-circuit string-vergelijking). Via nauwkeurige tijdmeting over honderden verzoeken kan een aanvaller het token teken-voor-teken reconstrueren zonder de volledige 64-karakter hex-digest te hoeven brute-forcen.
ImpactHerstel van het admin-token → volledige admintoegang (lees alle klant-PII, beheer producten/bestellingen).
// server/utils/auth.js:19-27 — PROBLEEM
if (token !== createAdminToken()) {   // ← niet constant-time!
  next(httpError(401, "Niet ingelogd als admin."));
}

// HERSTEL — gebruik crypto.timingSafeEqual
const expected = createAdminToken();
const tokBuf = Buffer.from(token.padEnd(expected.length, "\0"));
const expBuf = Buffer.from(expected);
if (!crypto.timingSafeEqual(tokBuf, expBuf)) { ... }
Kritiek SEC-002 Deterministisch, nooit-vervallend admin-token
Locatieserver/utils/auth.js:8–13 · AdminPage.jsx:74
CategorieAuthenticatie · CWE-613 · CWE-330
ProbleemToken = HMAC-SHA256(secret, "user:pass") — altijd dezelfde waarde, nooit vervallend, niet te invalideren zonder serverherstart. Opgeslagen in sessionStorage.
ImpactÉén gelekt token → permanente admintoegang. Uitloggen beëindigt enkel de browser-sessie, niet de server-sessie.
// server/utils/auth.js:8-13 — PROBLEEM
export function createAdminToken() {
  return crypto.createHmac("sha256", adminSecret)
    .update(`${adminUser}:${adminPassword}`)
    .digest("hex");  // ← deterministisch, geen expiry
}

// HERSTEL — willekeurige sessietoken met expiry
const sessions = new Map();
export function createSession() {
  const token = crypto.randomBytes(32).toString("hex");
  sessions.set(token, { expiresAt: Date.now() + 8 * 3600 * 1000 });
  return token;
}
Kritiek SEC-003 Hardgecodeerde standaardwachtwoorden + zichtbare hint
Locatieserver/utils/auth.js:4–6 · AdminPage.jsx:232 · server/openapi.js:144
CategorieAuthenticatie / Secrets · CWE-798 · OWASP A07:2021
ProbleemFallback-defaults admin/admin123/local-admin-secret actief wanneer env-vars ontbreken. De inlogpagina toont de credentials zichtbaar voor alle bezoekers. OpenAPI-spec documenteert dezelfde waarden.
ImpactIn elke misconfigureerde deployment logt elke bezoeker direct in als admin.
// server/utils/auth.js:4-6 — PROBLEEM
const adminPassword = process.env.ADMIN_PASSWORD || "admin123";
const adminSecret   = process.env.ADMIN_SECRET   || "local-admin-secret";

// HERSTEL — crash bij ontbrekende env-vars
if (!process.env.ADMIN_PASSWORD || !process.env.ADMIN_SECRET) {
  console.error("FATAL: ADMIN_PASSWORD en ADMIN_SECRET zijn vereist.");
  process.exit(1);
}

5. Hoge bevindingen Rembro Beveiligingsaudit 2026
5.Hoge bevindingen
Hoog SEC-004 Geen rate limiting op inlogendpunt
Locatieserver/routes/auth.js:8–24 · server/index.js
CategorieAuthenticatie · CWE-307 · OWASP A07:2021
ProbleemGeen express-rate-limit, geen account-lockout, geen CAPTCHA. Onbeperkt inlogpogingen per seconde mogelijk.
Herstelnpm install express-rate-limit — maximaal 10 pogingen per 15 minuten op POST /api/auth/login.
Hoog SEC-005 Wildcard CORS — alle origins toegestaan
Locatieserver/index.js:19
CategorieAPI-beveiliging · CWE-346 · OWASP A05:2021
Probleemapp.use(cors()) zonder configuratie staat alle origins toe. Een kwaadaardige website kan in de browser van een ingelogde beheerder GET /api/orders aanroepen en alle klant-PII uitlezen.
// HERSTEL
app.use(cors({
  origin: process.env.ALLOWED_ORIGIN || "http://localhost:5173",
  methods: ["GET", "POST", "PUT", "DELETE"],
  allowedHeaders: ["Content-Type", "Authorization"]
}));
Hoog SEC-006 Geen beveiligingsheaders — geen helmet, geen CSP, geen HSTS
Locatieserver/index.js (volledig ontbrekend)
Risico'sClickjacking (geen X-Frame-Options), MIME-sniffing (geen nosniff), geen XSS-barrière (geen CSP), geen HTTPS-afdwinging (geen HSTS).
Herstelnpm install helmet → app.use(helmet()) vóór alle routes. CSP toevoegen die unpkg.com toestaat voor Swagger UI.
Hoog SEC-007 Race condition in voorraadvermindering — overselling mogelijk
Locatieserver/routes/orders.js:82–131 · server/db/database.js:18
CategorieBedrijfslogica · CWE-362
ProbleemTransactie start met BEGIN (deferred). Twee gelijktijdige POST-verzoeken lezen beide stock=1, beide valideren succesvol, beiden maken een order aan. Stock wordt 2× verlaagd.
// server/db/database.js:18 — PROBLEEM
db.exec("BEGIN");  // ← deferred, geen schrijfslot bij aanvang

// HERSTEL
db.exec("BEGIN IMMEDIATE");  // ← schrijfslot direct, elimineert race
Hoog SEC-008 Geen idempotentie — dubbele bestelling bij dubbelklik
Locatieserver/routes/orders.js:78–137 · CheckoutPage.jsx:41
CategorieBedrijfslogica · CWE-362
ProbleemGeen duplicate-detectie. Dubbelklik of netwerkherpoging maakt twee identieke orders. Stock wordt tweemaal verlaagd.
HerstelUUID idempotencyKey genereren bij laden van afrekenformulier → meesturen in payload → UNIQUE-constraint op orders-tabel → bij duplicaat bestaande order teruggeven.

6. Gemiddelde bevindingen Rembro Beveiligingsaudit 2026
6.Gemiddelde bevindingen
GemiddeldSEC-009 SELECT * lekt alle productkolommen in orderverwerking
Locatieserver/routes/orders.js:84
ProbleemOrderverwerking gebruikt SELECT * FROM products i.p.v. expliciete kolomselectie. Toekomstige gevoelige kolommen (inkoopprijs, interne notities) worden automatisch meegenomen.
HerstelVervang door SELECT id, name, price, stock FROM products WHERE id = ?
GemiddeldSEC-010 Geen maximale stringlengte — opslag-DoS via publiek endpoint
Locatieserver/utils/validation.js:5–9
ProbleemrequireString controleert alleen minimumlengte. Anonieme bezoekers kunnen via POST /api/orders velden van bijna 1 MB insturen. Herhaling vult de SQLite-database en schijf totdat de applicatie faalt.
HerstelVoeg maxLength-parameter toe (bijv. 500 voor naam/adres, 5000 voor beschrijving).
GemiddeldSEC-011 requirePositiveNumber staat prijs = 0 toe
Locatieserver/utils/validation.js:12–18
ProbleemGrenswaarde is number < 0, waardoor 0 toegestaan is. Een (gecompromitteerde) beheerder kan productprijzen op €0 zetten.
HerstelGebruik number <= 0 voor het prijsveld of maak een aparte requirePrice-functie.
GemiddeldSEC-012 Onbeperkt orderregels — event-loop DoS via publiek endpoint
Locatieserver/routes/orders.js:44–60
ProbleemGeen bovengrens op body.items.length. Een verzoek met 10.000 items voert 10.000 synchrone SELECT-queries uit en blokkeert de Node.js event loop voor alle andere verzoeken. Geen auth vereist.
HerstelVoeg toe: if (body.items.length > 50) throw httpError(400, "Max. 50 producten per bestelling.");
GemiddeldSEC-013 Swagger UI via CDN zonder SRI + persistAuthorization actief
Locatieserver/openapi.js:323–329
ProbleemJavaScript geladen van unpkg.com zonder Subresource Integrity (SRI). Bij CDN-compromittering draait kwaadaardig script in Swagger-context. persistAuthorization: true slaat admin-tokens op in localStorage.
HerstelBundel Swagger UI lokaal als npm-dependency. Zet persistAuthorization: false. Overweeg /api-docs te blokkeren in productie.
GemiddeldSEC-014 Fouthandler logt volledige stacktraces naar stdout
Locatieserver/index.js:53–58
Probleemconsole.error(err) logt volledige Error-objecten inclusief bestandspaden en regelnummers. In cloud-omgevingen met brede log-toegang lekken implementatiedetails.
HerstelLogs behouden voor beheerder, maar stuur bij 5xx-fouten alleen een generieke boodschap naar de client: if (status >= 500) message = "Serverfout."
GemiddeldSEC-015 Container draait als root
LocatieDockerfile (geen USER-directive)
ProbleemNode.js-applicatie draait als UID 0 (root) in de container. Bij exploitatie van een dependency-kwetsbaarheid krijgt de aanvaller root-toegang in de container.
HerstelRUN adduser --system rembro + USER rembro toevoegen in de runtime-stage van het Dockerfile.
GemiddeldSEC-016 Klant-PII opgeslagen zonder AVG-retentiebeleid of verwijdermechanisme
Locatieserver/db/database.js:44–56
CategorieAVG/GDPR · Art. 17 · Art. 83
ProbleemNaam, e-mail, telefoon, adres worden opgeslagen zonder: bewaartermijn, anonimiseringsmechanisme, klant-verwijderverzoek (recht op vergetelheid), privacyverklaring.
ImpactPotentiële AVG-boete tot 4% jaaromzet of €20M (Art. 83 GDPR).
HerstelDefinieer bewaartermijn. Implementeer anonimisatie na retentieperiode. Voeg privacyverklaring toe aan de webshop.

LaagSEC-017 Winkelwagenprijzen in localStorage (server herberekent correct)
Locatieclient/src/context/CartContext.jsx:19
ProbleemPrijzen opgeslagen in localStorage. Weergave kan afwijken van werkelijke prijs als localStorage wordt gemanipuleerd. De server herberekent echter altijd het totaal vanuit de database — geen financieel risico.
HerstelSla geen prijs op in localStorage. Laad actuele prijs bij het openen van de afrekenenpagina opnieuw van de API.
LaagSEC-018 Adminpagina publiek bereikbaar met credential-hint
Locatieclient/src/App.jsx:23 · AdminPage.jsx:232
Probleem/admin is een publieke route. API-endpoints zijn correct beveiligd, maar de inlogpagina met credential-hint is zichtbaar voor alle bezoekers (verergert SEC-003).
HerstelVerwijder credential-hint (gedekt in SEC-003). Overweeg een minder voor de hand liggend adminpad.
LaagSEC-019 Bestellingenlijst zonder paginering — groeit onbeperkt
Locatieserver/routes/orders.js:63–66
ProbleemGET /api/orders retourneert alle bestellingen in één response. Bij groeiend volume: grote JSON-blob met veel klant-PII, performance-problemen en gegevensminimalisatierisico.
HerstelVoeg LIMIT en OFFSET toe via query-parameters: GET /api/orders?page=1&limit=50.
LaagSEC-020 Productafbeelding accepteert willekeurige externe URL's
Locatieserver/routes/products.js:28
ProbleemHet image-veld accepteert elke URL. Een gecompromitteerde adminaccount kan tracking pixels, SSRF-probes of ongepaste content instellen als afbeelding.
HerstelValideer URL tegen een allowlist van vertrouwde domeinen, of implementeer afbeeldingsuploads naar eigen opslag.
InfoSEC-021 id/slug-lookup gebruikt correct prepared statement — geen SQL-injectie
Locatieserver/routes/products.js:43
BevindingWHERE id = ? OR slug = ? met req.params.id voor beide parameters. SQLite coerceert het type correct. Geen SQL-injectierisico. Geflagd voor volledigheid als bevestiging van correcte implementatie.

9–10. Positief & Verificatie Rembro Beveiligingsaudit 2026
9.Positieve bevindingen
De volgende beveiligingspraktijken zijn correct geïmplementeerd en verdienen erkenning.
✓
Server-side prijsherberekening (orders.js:93–95) — het ordertotaal wordt altijd herberekend vanuit de database. Prijsmanipulatie via de client heeft geen effect. Dit is de meest kritische bedrijfslogica-beveiliging in een webshop en is correct gedaan.
✓
Geparameteriseerde queries door de gehele codebase — alle SQL gebruikt prepared statements. Geen string-concatenatie met gebruikersinvoer. Geen SQL-injectie aangetroffen.
✓
Auth-middleware consistent op alle admin-routes — elke muterende en admin-lees-route past requireAdmin toe. Geen ontbrekende autorisatiecheck gevonden op backend-routes.
✓
Transactionele orderverwerking (database.js:17–27) — aanmaak van order, orderregels en voorraadvermindering zijn atomair. Partial writes worden terugedraaid bij fouten.
✓
Foreign keys ingeschakeld (PRAGMA foreign_keys = ON) — referentiële integriteit gewaarborgd in SQLite.
✓
Geen dangerouslySetInnerHTML of .innerHTML — in geen enkel React-component is een XSS-sink aangetroffen. Alle gebruikersdata via React's DOM-abstractie.
✓
Statuswaarden op allowlist gevalideerd — orderstatussen worden gevalideerd tegen een expliciete allowedStatuses-lijst; willekeurige waarden worden geweigerd.
✓
docker-compose vereist env-vars (${VAR:?message}-syntaxis) — docker-compose weigert op te starten als ADMIN_PASSWORD en ADMIN_SECRET ontbreken.
✓
SQLite-bestand uitgesloten van deploypakket — CI-workflow sluit *.sqlite expliciet uit, zodat productiedata niet per ongeluk wordt overschreven.
10.Handmatige verificatie vereist
De volgende punten zijn niet vanuit statische code-analyse vast te stellen en vereisen controle op het live systeem of in de hostingomgeving.
⚠
TLS/HTTPS in productie — Dockerfile exposeert poort 3001 zonder TLS. Controleer of een reverse proxy (nginx, Caddy) HTTPS afhandelt. Zonder TLS worden admin-token en klantgegevens onversleuteld verstuurd.
⚠
SQLite-concurrency-modus — node:sqlite is experimenteel in Node.js 24. Controleer PRAGMA journal_mode; en PRAGMA locking_mode; — dit beïnvloedt de ernst van SEC-007.
⚠
Firewallconfiguratie — Is poort 3001 direct publiek toegankelijk of alleen via reverse proxy op localhost? Controleer op het productiesysteem.
⚠
Toegang tot Docker-logs — console.error() met stacktraces gaat naar Docker log driver. Controleer of logs toegankelijk zijn voor ongeautoriseerde partijen in de cloud-hostingomgeving.
⚠
Docker volume-isolatie — Is het rembro-data-volume (SQLite) bereikbaar vanuit andere containers of de Docker host?
⚠
Toekomstige betalingsprovider — Bij toevoeging van Mollie/Stripe: webhook-signatureverificatie implementeren vóór orderstatuswijziging naar "betaald". Nooit vertrouwen op client-redirect alleen.
